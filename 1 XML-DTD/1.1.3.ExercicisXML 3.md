# PRÀCTICA — TEXT, ESPAIS DE NOMS I COMPROVACIÓ D’XML

## Procediment

Crea els fitxers dins del projecte i comprova amb WebStorm que estan ben formats.

Conserva totes les dades dels enunciats. No elimines informació per fer desaparéixer errors.

---

## 1. Corregir un avís amb caràcters especials

**Fitxer:** `avis.xml`.

Una plataforma necessita guardar este avís, però el document conté errors:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<avis id="av01" titol="Revisió "urgent" del servidor">
    <servei>Còpies & restauració</servei>
    <missatge>Si l'espai lliure < 15, avisa l'administrador.</missatge>
    <documentacio>https://exemple.org/ajuda?tema=copies&idioma=va</documentacio>
    <instruccio>Obri Configuració i selecciona Còpies de seguretat.</instruccio>
    <!-- Revisió -- pendent de confirmar -->
</avis>
```

1. Corregix els caràcters especials utilitzant **entitats**, sense CDATA.
2. Conserva les cometes que envolten `"urgent"`. Els valors dels atributs han de continuar delimitats per cometes dobles.
3. Corregix el comentari conservant la informació que aporta.
4. Modifica `<instruccio>` perquè continga dos elements `<opcio>`:
   - un amb el text `Configuració`;
   - un altre amb el text `Còpies de seguretat`.

La resta de la frase ha de continuar com a text dins de `<instruccio>`. Conserva l’ordre de les paraules i els espais necessaris.

## 2. Guardar fragments de codi com a text

**Fitxers:** `exemples-cdata.xml` i `exemples-entitats.xml`.

Una aplicació necessita guardar els fragments següents per mostrar-los com a exemples. Les marques que apareixen en el codi han de conservar-se **com a text**, sense convertir-se en elements del document XML.

### Dades que has de guardar

**Exemple `e01` — Condició d’accés:**

```javascript
if (intents < 3 && actiu) {
    mostrar("Accés permés");
}
```

**Exemple `e02` — Explicació d’una entitat:**

```html
<p>Utilitza &lt; per representar el signe menor que.</p>
```

### Primera versió: amb CDATA

Crea `exemples-cdata.xml` amb:

- una arrel `<exemples>`;
- dos elements `<exemple>`, amb els atributs `id="e01"` i `id="e02"`;
- dins de cada exemple, un `<titol>` i un `<codi>`;
- el fragment corresponent dins d’una secció **CDATA** en `<codi>`.

Afig abans del primer exemple un comentari XML amb el text:

```text
Els fragments es guarden com a text, no com a elements XML.
```

### Segona versió: amb entitats

Duplica el document amb el nom `exemples-entitats.xml`.

Substituïx les seccions CDATA per text amb les **entitats necessàries**, conservant els fragments originals, els salts de línia i la indentació interior del codi.

> **Important:** En l’exemple `e02`, el text guardat ha de contindre literalment `&lt;`, és a dir, els quatre caràcters `&`, `l`, `t` i `;`. No ha de quedar substituït únicament pel signe `<`.

## 3. Crear un enviament amb dos vocabularis

**Fitxer:** `enviament.xml`.

Una empresa necessita reunir les dades del client i del transportista en un únic document XML.

### Dades del client

| Dada | Valor |
|---|---|
| Identificador | `c07` |
| Nom | Taller Nord |
| Codi | `CLI-007` |
| Carrer | Carrer Major, 18 |
| Localitat | La Vall d’Uixó |
| Codi postal | `12600` |
| Nom de la persona de contacte | Núria Vidal |
| Telèfon de contacte | `964123456` |

### Dades del transportista

| Dada | Valor |
|---|---|
| Identificador | `t02` |
| Nom | Ruta Express |
| Codi | `TR-002` |
| Servici | Entrega en 24 hores |
| Nom de la persona de contacte | Marc Ferrer |
| Telèfon de contacte | `964654321` |

### Condicions del document

1. Utilitza `<enviament>` com a únic element arrel.
2. Representa el client amb `<client>` i el transportista amb `<transportista>`, tots dos fills de l’arrel.
3. Guarda els identificadors en atributs `id`. Representa la resta de dades amb elements.
4. Agrupa:
   - el carrer, la localitat i el codi postal dins d’un element d’adreça;
   - el nom i el telèfon de cada persona dins d’un element de contacte.
5. Utilitza l’etiqueta `<nom>` tant per al nom del client i del transportista com per al de les persones de contacte.
6. Declara en l’arrel estos espais de noms:

   | Vocabulari | Prefix | URI |
   |---|---|---|
   | Comercial | `com` | `https://exemple.org/comercial` |
   | Logístic | `log` | `https://exemple.org/logistica` |

7. Aplica el prefix `com` al client i a tots els seus elements descendents.
8. Aplica el prefix `log` al transportista i a tots els seus elements descendents.

L’arrel `<enviament>` i els atributs `id` han de quedar **sense espai de noms**.

## 4. Incorporar un gràfic SVG dins d’un informe

**Fitxers:** `informe.xml` i `informe-prefix.xml`.

El document següent està ben format, però els elements gràfics no pertanyen a l’espai de noms SVG:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<informe xmlns="https://exemple.org/informes" id="inf01">
    <titol>Ocupació de les aules</titol>
    <resum>Distribució dels llocs disponibles.</resum>
    <grafic>
        <svg width="240" height="100">
            <rect x="10" y="10"
                  width="160" height="40"
                  fill="orange"/>
            <text x="10" y="80">16 llocs ocupats</text>
        </svg>
    </grafic>
</informe>
```

### Primera versió: sense prefixos

Copia el document en `informe.xml` i modifica les declaracions d’espais de noms perquè es complisca esta distribució:

| Elements | Espai de noms |
|---|---|
| `informe`, `titol`, `resum` i `grafic` | `https://exemple.org/informes` |
| `svg`, `rect` i `text` | `http://www.w3.org/2000/svg` |

Utilitza exclusivament **espais de noms per defecte**, sense prefixos.

### Segona versió: amb prefix SVG

Crea `informe-prefix.xml` a partir de la versió corregida:

1. Conserva l’espai de noms per defecte de l’informe.
2. Declara el prefix `svg` en l’arrel, associat a `http://www.w3.org/2000/svg`.
3. Utilitza eixe prefix en tots els elements gràfics.
4. Elimina la declaració per defecte del vocabulari SVG que havies afegit en la primera versió.

En les dos versions, conserva tots els textos i valors dels atributs. Els atributs han de continuar sense prefix.

## 5. Comprovar els límits del comprovador XML

**Document de partida:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<reserva id="r01">
    <client>Mar Soler</client>
    <entrada>2026-11-12</entrada>
    <eixida>2026-11-15</eixida>
    <persones>2</persones>
</reserva>
```

L’aplicació que rep les reserves exigix:

- una arrel `<reserva>` amb l’atribut `id`;
- exactament estos elements fills, una vegada i en este ordre: `<client>`, `<entrada>`, `<eixida>` i `<persones>`;
- un nombre enter positiu en `<persones>`;
- una data d’eixida posterior a la d’entrada.

Crea **tres còpies independents del document original**:

| Fitxer | Modificació que has de fer |
|---|---|
| `reserva-a.xml` | Provoca un únic error de sintaxi que impedisca que el document estiga ben format. |
| `reserva-b.xml` | Modifica els elements fills o el seu ordre perquè incomplisquen l’estructura exigida. El document ha de continuar ben format. |
| `reserva-c.xml` | Canvia un valor perquè incomplisca les condicions de la reserva. Conserva la sintaxi i l’estructura exigides. |

Comprova els tres fitxers amb WebStorm. Conserva les modificacions demanades en els documents que entregues, inclòs l’error intencionat de `reserva-a.xml`.

> Sense una DTD o un esquema associat, comprovar que l’XML està ben format no permet assegurar que complix totes les condicions de l’aplicació.
