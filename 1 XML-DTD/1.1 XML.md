# XML — Definició, estructura i regles bàsiques

XML és un llenguatge de marques utilitzat per guardar, organitzar i intercanviar informació de manera estructurada.

En este apartat estudiarem:

- la finalitat d’XML;
- l’estructura d’un document XML;
- les regles que ha de complir;
- la representació d’informació mitjançant elements i atributs;
- els caràcters especials, els comentaris i les seccions CDATA;
- els espais de noms;
- la diferència entre un document ben format i un document vàlid.

---

## 1. Què és XML i per a què s’utilitza?

XML són les sigles de:

**eXtensible Markup Language**, que podriem traduir com a **Llenguatge de Marques Extensible**.

Per tant **XML** és un llenguatge de marques que utilitza **etiquetes** per **descriure i organitzar** informació.

```xml
<videojoc>
    <titol>Minecraft</titol>
    <plataforma>Multiplataforma</plataforma>
</videojoc>
```

En este fragment podem identificar fàcilment:

- un videojoc representat per `<videojoc>`;
- el seu títol representat per `<titol>`;
- la plataforma representada per `<plataforma>`.

> **Idea clau**
>
> XML permet indicar què representa cada dada mitjançant etiquetes.

**Un llenguatge extensible.**

XML **no** proporciona una llista **tancada d’etiquetes**. Les etiquetes es definixen segons la informació que es vol representar.

Per exemple, una aplicació es podria descriure així:

```xml
<aplicacio>
    <nom>Visual Studio Code</nom>
    <sistema>Multiplataforma</sistema>
</aplicacio>
```

Les etiquetes `<aplicacio>`, `<nom>` i `<sistema>` no formen part d’una llista proporcionada per XML. S’han creat específicament per representar eixa informació.

### Usos d’XML

XML s’utilitza per guardar i intercanviar dades, configurar aplicacions i descriure documents o continguts especialitzats.

Alguns exemples reals són:

| Tecnologia o fitxer | Utilització |
|---|---|
| `pom.xml` | Configuració de projectes Maven |
| `AndroidManifest.xml` | Configuració d’aplicacions Android |
| SVG | Representació de gràfics vectorials |
| RSS i Atom | Distribució de notícies i continguts |
| MathML | Representació de fórmules matemàtiques |
| Documents d’Office | Utilitzen internament diversos fitxers XML |
| Fitxers de configuració | Configuració d’aplicacions i servicis |

Encara que actualment també s’utilitzen formats com JSON, XML continua sent important en aplicacions empresarials, servicis web, ferramentes de desenvolupament i nombrosos estàndards.

### Què no és XML?

**XML no és un llenguatge de programació.**

XML no conté instruccions, condicions o bucles.

Este document guarda informació:

```xml
<jugador>
    <nom>Jaume</nom>
    <nivell>25</nivell>
</jugador>
```

Però no indica què ha de fer una aplicació amb eixa informació.

**XML no establix, per si mateix, una presentació visual.**

L’aspecte del document depén del vocabulari utilitzat i de l’aplicació que l’interpreta.

Per exemple:

- un catàleg XML descriu dades sobre videojocs;
- SVG utilitza XML per descriure formes, colors i posicions.

En obrir un fitxer XML de dades amb el navegador, normalment es mostra la seua estructura. Les etiquetes pròpies, com `<videojoc>` o `<titol>`, no tenen una aparença visual definida.

### Diferències entre XML i HTML

XML i HTML utilitzen etiquetes, però tenen finalitats diferents.

| XML | HTML |
|---|---|
| Descriu i organitza informació estructurada | Estructura i dona significat al contingut d’una pàgina web |
| Permet definir etiquetes pròpies | Utilitza un vocabulari d’etiquetes definit per l’estàndard |
| Exigix una sintaxi estricta | El navegador pot recuperar-se de molts errors de sintaxi |
| Diferencia majúscules i minúscules | Els noms de les etiquetes HTML no distingixen majúscules i minúscules |

Exemple XML:

```xml
<videojoc>
    <titol>Fortnite</titol>
</videojoc>
```

Exemple HTML:

```html
<h1>Fortnite</h1>
```

En XML, `<titol>` indica que `Fortnite` és el títol d’un videojoc.

En HTML, `<h1>` indica que `Fortnite` és l’encapçalament principal d’una pàgina.

**Tecnologies relacionades.**

XML forma part d’un conjunt ampli de tecnologies.

Esta relació servix únicament per situar XML dins del seu ecosistema. En este tema continuarem amb DTD.

| Tecnologia | Finalitat |
|---|---|
| DTD | Definir l’estructura que ha de complir un document |
| XML Schema | Definir estructures i tipus de dades |
| XPath | Localitzar informació dins d’un document |
| XSLT | Transformar documents XML |
| SVG | Representar gràfics vectorials |
| MathML | Representar fórmules matemàtiques |

## 2. Estructura d’un document XML

Els documents XML solen guardar-se en fitxers amb l’extensió `.xml`, per exemple, `videojocs.xml`.

Un document XML senzill pot ser:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<videojoc id="j01">
    <titol>Minecraft</titol>
    <plataforma>Multiplataforma</plataforma>
</videojoc>
```

Este document conté:

- una declaració XML;
- un element arrel;
- diversos elements;
- un atribut;
- contingut de text.

### Declaració XML

La primera línia és la declaració XML:

```xml
<?xml version="1.0" encoding="UTF-8"?>
```

La declaració proporciona informació sobre el document.

**Versió.** `version="1.0"` indica la versió d’XML utilitzada. En els documents del curs utilitzarem XML 1.0.

**Codificació.** `encoding="UTF-8"` indica la codificació dels caràcters.

UTF-8 permet representar correctament:

- accents;
- apòstrofs;
- la ce trencada;
- caràcters de diferents idiomes;
- símbols especials.

> **Important**
>
> Indicar `encoding="UTF-8"` no canvia automàticament la codificació del fitxer. El document també ha d’estar guardat realment en UTF-8.

La declaració XML és opcional en determinats documents, però és recomanable utilitzar-la per indicar clarament la versió i la codificació.

Si apareix, ha d’estar al principi del document, sense text ni comentaris abans.

### Components principals

Observa el fragment següent:

```xml
<titol>Minecraft</titol>
```

Podem diferenciar:

| Part | Exemple |
|---|---|
| Etiqueta d’obertura | `<titol>` |
| Contingut de text | `Minecraft` |
| Etiqueta de tancament | `</titol>` |
| Element complet | `<titol>Minecraft</titol>` |

La barra `/` permet identificar l’etiqueta de tancament.

> **Error habitual**
>
> Una etiqueta no és el mateix que un element. `<titol>` és una etiqueta, mentre que `<titol>Minecraft</titol>` és un element complet.

**Element arrel.**

Tot document XML ha de tindre un únic element principal anomenat **element arrel**.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<cataleg>
    <videojoc>
        <titol>Minecraft</titol>
    </videojoc>
    <videojoc>
        <titol>Fortnite</titol>
    </videojoc>
</cataleg>
```

En este document, `<cataleg>` és l’element arrel perquè conté la resta d’elements.

**Atributs.**

Els atributs afigen informació a un element.

```xml
<videojoc id="j01">
    <titol>Minecraft</titol>
</videojoc>
```

En l’etiqueta:

```xml
<videojoc id="j01">
```

podem identificar:

- `videojoc`: nom de l’element;
- `id`: nom de l’atribut;
- `j01`: valor de l’atribut.

Un element pot tindre diversos atributs:

```xml
<videojoc id="j01" disponible="si">
    <titol>Minecraft</titol>
</videojoc>
```

Els atributs sempre formen part de l’etiqueta d’obertura.

**Elements buits.**

Un element buit no conté text ni elements fills, però pot tindre atributs.

```xml
<imatge src="minecraft.png"></imatge>
```

Es pot escriure de manera abreujada:

```xml
<imatge src="minecraft.png"/>
```

Les dos formes representen el mateix element buit.

La presència de `<imatge>` no fa que el navegador mostre automàticament una imatge. El significat de l’element i dels seus atributs el determina l’aplicació que interpreta el document.

### Estructura jeràrquica

Els elements poden contindre altres elements.

```xml
<cataleg>
    <videojoc>
        <titol>Minecraft</titol>
        <plataforma>Multiplataforma</plataforma>
    </videojoc>
</cataleg>
```

La jerarquia del document és:

- `cataleg`
    - `videojoc`
        - `titol`
        - `plataforma`

En esta estructura:

- `<cataleg>` és el pare de `<videojoc>`;
- `<videojoc>` és fill de `<cataleg>`;
- `<titol>` i `<plataforma>` són fills de `<videojoc>`;
- `<titol>` i `<plataforma>` són elements germans.

**Indentació.**

La indentació utilitza espais per mostrar visualment la jerarquia.

Document sense una indentació clara:

```xml
<cataleg><videojoc><titol>Minecraft</titol><plataforma>Multiplataforma</plataforma></videojoc></cataleg>
```

El mateix document indentat:

```xml
<cataleg>
    <videojoc>
        <titol>Minecraft</titol>
        <plataforma>Multiplataforma</plataforma>
    </videojoc>
</cataleg>
```

Els dos documents poden estar ben formats, però el segon és més fàcil de llegir i mantindre.

> **Idea clau**
>
> La jerarquia la determinen les etiquetes. La indentació només ajuda a visualitzar-la.

## 3. Regles dels documents XML

Un document XML ha de complir unes regles sintàctiques.

Quan complix totes estes regles, diem que està **ben format**.

**Ha d’existir un únic element arrel.**

Incorrecte:

```xml
<videojoc>Minecraft</videojoc>
<videojoc>Fortnite</videojoc>
```

El document té dos elements principals.

Correcte:

```xml
<cataleg>
    <videojoc>Minecraft</videojoc>
    <videojoc>Fortnite</videojoc>
</cataleg>
```

`<cataleg>` és l’únic element arrel.

**Tots els elements han de tindre tancament.**

Cada element ha de tindre una etiqueta de tancament o, si està buit, utilitzar la forma abreujada `<element/>`.

Incorrecte:

```xml
<videojoc>
    <titol>Minecraft
</videojoc>
```

Falta l’etiqueta de tancament de `<titol>`.

Correcte:

```xml
<videojoc>
    <titol>Minecraft</titol>
</videojoc>
```

**Les etiquetes s’han d’imbricar correctament.**

Incorrecte:

```xml
<videojoc>
    <titol>Minecraft
</videojoc>
    </titol>
```

S’ha tancat `<videojoc>` abans de tancar `<titol>`.

Correcte:

```xml
<videojoc>
    <titol>Minecraft</titol>
</videojoc>
```

Les etiquetes funcionen com caixes. Si una caixa s’obri dins d’una altra, s’ha de tancar abans.

**XML diferencia majúscules i minúscules.**

Incorrecte:

```xml
<titol>Minecraft</Titol>
```

`<titol>` i `<Titol>` són noms diferents.

Correcte:

```xml
<titol>Minecraft</titol>
```

També seria sintàcticament correcte:

```xml
<Titol>Minecraft</Titol>
```

Però és recomanable mantindre un criteri uniforme. En els documents del curs utilitzarem preferentment noms en minúscules.

**Els noms han de ser correctes.**

Els noms dels elements i dels atributs:

- no poden contindre espais;
- poden començar per una lletra o `_`, però no per una xifra, un guionet o un punt;
- diferencien majúscules i minúscules.

Els noms que comencen per `xml`, en qualsevol combinació de majúscules i minúscules, estan reservats per als estàndards XML.

Els dos punts `:` s’utilitzen per separar el prefix i el nom local quan treballem amb espais de noms.

A més de respectar estes regles, convé utilitzar noms clars i descriptius.

Incorrecte:

```xml
<nom videojoc>Minecraft</nom videojoc>
```

Correcte:

```xml
<nom_videojoc>Minecraft</nom_videojoc>
```

Incorrecte:

```xml
<1videojoc>Minecraft</1videojoc>
```

Correcte:

```xml
<videojoc1>Minecraft</videojoc1>
```

Per facilitar la lectura, en el curs utilitzarem:

- minúscules;
- noms sense espais;
- noms sense accents;
- `_` per separar paraules quan siga necessari;
- paraules descriptives.

Exemples:

```xml
<nom_complet>Àlex García</nom_complet>
<data_publicacio>2026-09-28</data_publicacio>
<sistema_operatiu>LliureX</sistema_operatiu>
```

XML permet molts caràcters Unicode en els noms. Evitar accents és una convenció de treball, no una limitació absoluta del llenguatge. Esta convenció només s’aplica als noms d’elements i atributs: el contingut conserva els accents i la seua escriptura correcta.

**Els valors dels atributs han d’estar entre cometes.**

Incorrecte:

```xml
<videojoc id=j01>
```

Correcte:

```xml
<videojoc id="j01">
```

També es poden utilitzar apòstrofs:

```xml
<videojoc id='j01'>
```

En els documents del curs utilitzarem preferentment cometes dobles.

**Un atribut no es pot repetir.**

Incorrecte:

```xml
<videojoc id="j01" id="j02">
```

Correcte:

```xml
<videojoc id="j01">
```

Un mateix element no pot tindre dos atributs amb el mateix nom.

**L’ordre dels atributs no altera el significat.**

Estos dos elements representen la mateixa informació:

```xml
<videojoc id="j01" disponible="si">
```

```xml
<videojoc disponible="si" id="j01">
```

Tot i això, mantindre sempre un ordre coherent facilita la lectura.

**L’ordre dels elements fills pot ser important.**

A diferència dels atributs, els elements fills formen una seqüència ordenada.

```xml
<ruta>
    <parada>València</parada>
    <parada>Castelló</parada>
</ruta>
```

Si invertim les parades, representem un recorregut diferent.

L’ordre també pot estar fixat per les regles d’una DTD.

**El contingut ha d’estar dins de l’element arrel.**

Incorrecte:

```xml
Catàleg de videojocs
<cataleg>
    <videojoc>Minecraft</videojoc>
</cataleg>
```

El text `Catàleg de videojocs` es troba fora de l’element arrel.

Correcte:

```xml
<cataleg>
    <titol>Catàleg de videojocs</titol>
    <videojoc>Minecraft</videojoc>
</cataleg>
```

Fora de l’element arrel poden aparéixer determinades construccions, com la declaració XML, comentaris o instruccions de processament, però no les dades principals del document.

## 4. Com es representa la informació?

Dissenyar un document XML implica decidir:

- quin serà l’element arrel;
- quins objectes es repetixen;
- quina informació conté cada objecte;
- quines dades es representen amb elements;
- quines dades es representen amb atributs.

Suposem que volem representar este catàleg:

| ID | Títol | Plataforma | Gènere |
|---|---|---|---|
| j01 | Minecraft | Multiplataforma | Construcció i supervivència |
| j02 | Fortnite | Multiplataforma | Acció |
| j03 | Grand Theft Auto V | PC i consoles | Acció i món obert |
| j04 | Mario Kart 8 Deluxe | Nintendo Switch | Carreres |

El conjunt complet es pot representar amb un element `<cataleg>`.

Cada fila de la taula representa un `<videojoc>`.

Les propietats de cada videojoc es representen amb elements fills:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<cataleg>
    <videojoc id="j01">
        <titol>Minecraft</titol>
        <plataforma>Multiplataforma</plataforma>
        <genere>Construcció i supervivència</genere>
    </videojoc>
    <videojoc id="j02">
        <titol>Fortnite</titol>
        <plataforma>Multiplataforma</plataforma>
        <genere>Acció</genere>
    </videojoc>
    <videojoc id="j03">
        <titol>Grand Theft Auto V</titol>
        <plataforma>PC i consoles</plataforma>
        <genere>Acció i món obert</genere>
    </videojoc>
    <videojoc id="j04">
        <titol>Mario Kart 8 Deluxe</titol>
        <plataforma>Nintendo Switch</plataforma>
        <genere>Carreres</genere>
    </videojoc>
</cataleg>
```

En este model:

- `<cataleg>` representa el conjunt;
- cada `<videojoc>` representa un objecte;
- `<titol>`, `<plataforma>` i `<genere>` representen les seues dades;
- `id` identifica cada videojoc.

### Elements o atributs?

Una mateixa informació es pot representar de maneres diferents.

Amb un element:

```xml
<videojoc>
    <plataforma>PC</plataforma>
</videojoc>
```

Amb un atribut:

```xml
<videojoc plataforma="PC">
</videojoc>
```

Les dos opcions poden estar ben formades, però no sempre són igualment adequades.

**Els elements són adequats quan la informació:**

- és una dada principal;
- pot contindre text llarg;
- pot repetir-se;
- pot tindre estructura interna;
- pot necessitar altres elements o atributs.

```xml
<videojoc>
    <titol>League of Legends</titol>
    <descripcio>
        Videojoc competitiu en línia basat en equips.
    </descripcio>
</videojoc>
```

**Els atributs són adequats quan la informació:**

- identifica l’element;
- és breu;
- funciona com a metadada;
- classifica l’element;
- complementa el valor principal.

Una **metadada** és informació que descriu o dona context a una dada principal.

```xml
<videojoc id="j05" disponible="si">
    <titol>League of Legends</titol>
</videojoc>
```

Elements i atributs també poden combinar-se:

```xml
<preu moneda="EUR">29.99</preu>
```

En este cas:

- `29.99` és el valor principal;
- `moneda="EUR"` indica com s’ha d’interpretar.

**Un model poc clar.**

```xml
<videojoc
    id="j06"
    titol="Valorant"
    plataforma="PC"
    genere="Acció"
    descripcio="Videojoc competitiu per equips"/>
```

El document pot estar ben format, però concentrar tota la informació en atributs dificulta:

- la lectura;
- l’ampliació;
- la representació de textos llargs;
- la creació d’estructures més complexes.

Una estructura més clara seria:

```xml
<videojoc id="j06">
    <titol>Valorant</titol>
    <plataforma>PC</plataforma>
    <genere>Acció</genere>
    <descripcio>
        Videojoc competitiu per equips.
    </descripcio>
</videojoc>
```

> **Idea clau**
>
> No sempre existix una única estructura correcta. El model ha de ser coherent, fàcil de llegir i adequat per a la informació representada.

### Procés habitual de modelatge

La creació d’un model XML sol seguir este procés:

1. Identificar el conjunt d’informació i definir l’element arrel.
2. Identificar els objectes que es repetixen i definir els seus elements.
3. Determinar les propietats de cada objecte i les relacions entre elles.
4. Decidir quines propietats es representaran amb elements i quines amb atributs.
5. Comprovar el model amb més d’un objecte i revisar la jerarquia, l’ordre i la indentació.

## 5. Text i continguts especials

Un element pot contindre:

- **text**, com `<titol>Roblox</titol>`;
- **elements fills**, com un `<videojoc>` amb títol i plataforma;
- **contingut mixt**, que combina text i elements fills.

Exemple de contingut mixt:

```xml
<missatge>Actualitza el <aplicacio>navegador</aplicacio> abans de continuar.</missatge>
```

L’element `<missatge>` conté text i un element fill `<aplicacio>`.

Les dades de text dels elements i els valors dels atributs es representen com a seqüències de caràcters. XML, per si mateix, no els assigna automàticament tipus com enter, decimal o booleà.

```xml
<preu>29.99</preu>
<jugadors>100</jugadors>
<disponible>si</disponible>
```

Nosaltres podem interpretar:

- `29.99` com un nombre decimal;
- `100` com un nombre enter;
- `si` com un valor lògic.

Però XML, per si mateix, no imposa eixos tipus de dades. L’aplicació que processa el document o una tecnologia de validació determinarà com s’han d’interpretar. Per exemple, XML no interpreta automàticament `unitats="25"` com un nombre enter.

**Espais en el contingut.**

Els espais situats dins d’un element poden formar part del text.

```xml
<missatge>Hola jugador</missatge>
```

No representa exactament el mateix contingut que:

```xml
<missatge>  Hola jugador  </missatge>
```

Per això, la indentació s’ha d’aplicar entre els elements i no afegint espais innecessaris al contingut.

### Caràcters especials i entitats

Alguns caràcters tenen un significat especial en XML.

Per exemple, `<` indica el començament d’una etiqueta. Si forma part del text, s’ha de substituir per una entitat.

Incorrecte:

```xml
<condicio>nivell < 10</condicio>
```

Correcte:

```xml
<condicio>nivell &lt; 10</condicio>
```

XML proporciona cinc entitats predefinides:

| Caràcter | Entitat | Significat |
|---|---|---|
| `<` | `&lt;` | Menor que |
| `>` | `&gt;` | Major que |
| `&` | `&amp;` | Ampersand |
| `"` | `&quot;` | Cometes dobles |
| `'` | `&apos;` | Apòstrof |

Exemple amb un ampersand:

Incorrecte:

```xml
<empresa>Rockstar & Take-Two</empresa>
```

Correcte:

```xml
<empresa>Rockstar &amp; Take-Two</empresa>
```

Exemple dins d’un atribut:

```xml
<edicio nom="Versió &quot;Premium&quot;"/>
```

Les entitats sempre:

- comencen amb `&`;
- acaben amb `;`.

Incorrecte:

```xml
<condicio>nivell &lt 10</condicio>
```

Correcte:

```xml
<condicio>nivell &lt; 10</condicio>
```

No tots els caràcters s’han de substituir en totes les situacions:

- `&` s’ha de representar com `&amp;`;
- `<` s’ha de representar com `&lt;` quan forma part del text;
- `"` necessita `&quot;` principalment dins d’un atribut delimitat per cometes dobles;
- `'` necessita `&apos;` dins d’un atribut delimitat per apòstrofs;
- `>` normalment es pot escriure directament.

### Comentaris

Els comentaris permeten incloure explicacions que no formen part de les dades.

```xml
<!-- Catàleg de videojocs -->
<cataleg>
    <videojoc id="j01">
        <titol>Minecraft</titol>
    </videojoc>
</cataleg>
```

Un comentari comença amb `<!--` i acaba amb `-->`.

També pot ocupar diverses línies:

```xml
<!--
    Els videojocs estan ordenats
    alfabèticament pel seu títol.
-->
```

Els comentaris no poden contindre la seqüència `--`.

Incorrecte:

```xml
<!-- Videojocs -- disponibles -->
```

Correcte:

```xml
<!-- Videojocs disponibles -->
```

Tampoc es poden situar dins d’una etiqueta.

Incorrecte:

```xml
<videojoc <!-- identificador --> id="j01">
```

Correcte:

```xml
<!-- Identificador intern del videojoc -->
<videojoc id="j01">
```

Els comentaris han d’explicar decisions o informació útil. No és necessari comentar etiquetes que ja tenen un nom clar.

### Seccions CDATA

Una secció CDATA permet incloure text amb molts caràcters especials sense substituir-los per entitats.

```xml
<codi><![CDATA[
if (nivell < 10 && punts > 100) {
    System.out.println("Puja de nivell");
}
]]></codi>
```

La secció comença amb `<![CDATA[` i acaba amb `]]>`.

Dins de CDATA, `<` i `&` no s’interpreten com a marques XML.

Sense CDATA, el fragment anterior necessitaria entitats:

```xml
<codi>
if (nivell &lt; 10 &amp;&amp; punts &gt; 100) {
    System.out.println("Puja de nivell");
}
</codi>
```

CDATA pot resultar útil per guardar:

- fragments de codi;
- fórmules;
- exemples d’HTML o XML;
- text amb molts caràcters especials.

Les seccions CDATA tenen dos aspectes importants:

- les entitats no es processen dins de CDATA;
- no poden contindre la seqüència `]]>`.

> **Idea clau**
>
> CDATA no és necessària per al text normal. S’utilitza quan el contingut presenta molts caràcters que XML podria interpretar com a marques.

**Ampliació — Instruccions de processament.**

Les instruccions de processament proporcionen informació destinada a una aplicació que processarà el document.

```xml
<?xml-stylesheet type="text/xsl" href="estil.xsl"?>
```

Una instrucció de processament:

- comença amb `<?`;
- acaba amb `?>`;
- no forma part de les dades principals;
- està dirigida a un programa o processador.

En els primers documents només és necessari reconéixer esta construcció.

## 6. Espais de noms

XML permet definir etiquetes lliurement. Repetir un nom com `<nom>` en parts diferents d’un document no és necessàriament un problema, perquè la jerarquia pot diferenciar el seu significat.

Els **espais de noms** permeten identificar a quin vocabulari pertany cada element o atribut. Són especialment útils quan es combinen vocabularis XML diferents que utilitzen els mateixos noms.

### Declaració d’un espai de noms

```xml
<document
    xmlns:centre="https://exemple.org/centre"
    xmlns:pc="https://exemple.org/ordinadors">
    <centre:nom>IES Benigasló</centre:nom>
    <pc:nom>Equip aula 1</pc:nom>
</document>
```

En este exemple:

- `xmlns` declara un espai de noms;
- `centre` i `pc` són prefixos;
- els URI identifiquen els vocabularis;
- `<centre:nom>` i `<pc:nom>` deixen de ser elements ambigus.

**Prefix i nom local.** En `<centre:nom>` podem diferenciar:

- `centre`: prefix;
- `nom`: nom local de l’element.

Els prefixos són abreviatures triades en el document. La identitat real de l’espai de noms és el URI.

Per exemple, `xmlns:centre="https://exemple.org/centre"` i `xmlns:c="https://exemple.org/centre"` utilitzen prefixos diferents per identificar el mateix vocabulari.

**URI de l’espai de noms.** En `xmlns:centre="https://exemple.org/centre"`, el text `https://exemple.org/centre` és l’identificador de l’espai de noms.

Té forma d’adreça web per facilitar que siga únic, però no és obligatori que mostre una pàgina en obrir-lo amb el navegador.
Declarar un espai de noms identifica un vocabulari. No valida el document ni descarrega automàticament una DTD o un esquema.

**Declaració obligatòria del prefix.**

Un prefix no es pot utilitzar si no s’ha declarat.

Incorrecte:

```xml
<centre:alumne>
    <centre:nom>Marc</centre:nom>
</centre:alumne>
```

Correcte:

```xml
<centre:alumne xmlns:centre="https://exemple.org/centre">
    <centre:nom>Marc</centre:nom>
</centre:alumne>
```

La declaració està disponible per a tots els elements descendents:

```xml
<centre:alumnes xmlns:centre="https://exemple.org/centre">
    <centre:alumne>
        <centre:nom>Marc</centre:nom>
    </centre:alumne>
    <centre:alumne>
        <centre:nom>Laia</centre:nom>
    </centre:alumne>
</centre:alumnes>
```

> **Error habitual**
>
> Declarar un prefix permet utilitzar-lo en els elements descendents, però no l’aplica automàticament als seus noms.

```xml
<centre:alumne xmlns:centre="https://exemple.org/centre">
    <nom>Marc</nom>
</centre:alumne>
```

En este exemple, `<centre:alumne>` pertany a l’espai de noms declarat, però `<nom>` no. Perquè hi pertanga, cal escriure `<centre:nom>` o declarar un espai de noms per defecte.

### Espai de noms per defecte

Un espai de noms també es pot declarar sense prefix:

```xml
<cataleg xmlns="https://exemple.org/videojocs">
    <videojoc>
        <titol>Minecraft</titol>
    </videojoc>
</cataleg>
```

L’espai de noms per defecte s’aplica a:

- `<cataleg>`;
- `<videojoc>`;
- `<titol>`.

Això evita repetir el prefix en cada element.

> **Important**
>
> L’espai de noms per defecte s’aplica als elements sense prefix, però no als atributs sense prefix.

En este fragment:

```xml
<videojoc
    xmlns="https://exemple.org/videojocs"
    id="j01">
    <titol>Minecraft</titol>
</videojoc>
```

`<videojoc>` i `<titol>` pertanyen a l’espai de noms dels videojocs, però l’atribut `id` no pertany automàticament a eixe espai.

### Exemple real: SVG

SVG és un llenguatge basat en XML que permet crear gràfics vectorials.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<svg
    width="300"
    height="180"
    xmlns="http://www.w3.org/2000/svg">
    <rect
        x="20"
        y="20"
        width="260"
        height="140"
        fill="lightgray"/>
    <circle
        cx="80"
        cy="90"
        r="35"
        fill="orange"/>
    <text
        x="135"
        y="100"
        font-size="24">
        DAM
    </text>
</svg>
```

La declaració:

```xml
xmlns="http://www.w3.org/2000/svg"
```

indica que `<svg>`, `<rect>`, `<circle>` i `<text>` pertanyen al vocabulari SVG.

## 7. Documents ben formats i documents vàlids

Un analitzador XML, també anomenat **parser**, és un programa que llig un document XML i comprova la seua estructura.

Pot detectar errors com:

- etiquetes sense tancar;
- diferències entre majúscules i minúscules;
- imbricació incorrecta;
- més d’un element arrel;
- atributs sense cometes;
- atributs repetits;
- caràcters especials incorrectes;
- prefixos no declarats.

WebStorm analitza el document mentre s’escriu i marca molts d’estos errors.

Un navegador també pot mostrar el document i informar d’alguns errors de formació, però no s’ha de considerar un validador complet.

Opcionalment, si `xmllint` està instal·lat, es pot comprovar si el document està ben format:

```bash
xmllint --noout videojocs.xml
```

Si no apareix cap missatge, el document està ben format. Si existix un error, la ferramenta indica normalment la línia, la columna i el tipus de problema.

### Ben format o vàlid?

Un document és **vàlid respecte d’una DTD o d’un esquema** quan està ben format i complix les regles que estos definixen.

Estar ben format no implica ser vàlid. A més, superar la validació no garantix que totes les dades siguen correctes en la realitat.

**Un document ben format pot contindre dades inadequades.**

```xml
<videojoc>
    <preu>Minecraft</preu>
</videojoc>
```

Este document està ben format, però el contingut de `<preu>` no sembla adequat.

XML comprova l’estructura sintàctica, però no coneix automàticament el significat de les dades. Una DTD pot comprovar l’estructura i alguns tipus d’atributs, però no pot exigir que el text de `<preu>` siga un nombre decimal si l’element està declarat com a text. Per validar tipus com números o dates caldria XML Schema o una comprovació realitzada per l’aplicació.

**Document vàlid.**

Un document vàlid:

1. està ben format;
2. complix unes regles definides prèviament.

Per exemple, podríem establir que tot videojoc ha de contindre, en este ordre:

1. un títol;
2. una plataforma;
3. un gènere.

Este document compliria les regles:

```xml
<videojoc>
    <titol>Minecraft</titol>
    <plataforma>Multiplataforma</plataforma>
    <genere>Construcció i supervivència</genere>
</videojoc>
```

Este altre document també està ben format:

```xml
<joc>
    <nom>Minecraft</nom>
    <sistema>Multiplataforma</sistema>
</joc>
```

Però no seria vàlid si les regles exigiren:

```text
videojoc → titol, plataforma, genere
```

> **Idea clau**
>
> Primer es comprova si el document està ben format. Després es comprova si és vàlid respecte d’unes regles.

### Connexió amb DTD

XML permet crear etiquetes lliurement. Per això, dos documents ben formats poden representar la mateixa informació amb noms i estructures diferents.

Per exemple, una aplicació pot esperar un element `<videojoc>` amb `<titol>` i `<plataforma>`, però rebre un `<joc>` amb `<nom>` i `<sistema>`. Encara que el document estiga ben format, no seguix l’estructura esperada.

Una **DTD** permet establir un vocabulari i unes regles comunes:

- quins elements poden aparéixer;
- en quin ordre;
- quantes vegades poden repetir-se;
- quins atributs estan permesos;
- quins atributs són obligatoris.

En el següent apartat veurem com escriure estes regles i validar els documents.
