# Pràctiques amb XML i DTD


### Pràctica 1 — Panell de vols

Crea un document XML que emmagatzeme la informació mostrada en un panell de vols d’un aeroport.

La DTD haurà d’estar declarada dins del mateix document XML.

- **Requisits**

El document haurà de contindre:

- El nom de l’aeroport.
- La data del panell.
- Una llista amb un o més vols.

De cada vol s’haurà d’indicar la informació que apareix en el panell: hora, destinació, companyia, número de vol, porta d’embarcament o qualsevol altra dada representada.

Cada vol tindrà els atributs següents:

- `codi`: identificador únic i obligatori de tipus `ID`.
- `estat`: podrà tindre els valors `C`, `E` o `R`.
  - `C`: cancel·lat.
  - `E`: en hora.
  - `R`: retardat.
  - El valor predeterminat serà `E`.

Els vols que operen diàriament podran incloure un element buit anomenat `diari`. Aquest element serà opcional.

- **Lliurament**

S’haurà de lliurar un únic fitxer XML que continga:

- La declaració XML.
- La DTD interna.
- Les dades del panell de vols.

El document haurà d’estar ben format i validar correctament respecte de la DTD.

### Pràctica 2 — Factura

Crea un document XML que represente una factura i defineix la seua estructura mitjançant una DTD interna.

- **Requisits**

L’element principal serà `factura` i tindrà els atributs següents:

- `numero`: número identificador de la factura.
- `data`: data d’emissió de la factura.

La factura estarà formada pels blocs següents:

1. Dades de l’emissor.
2. Dades del client.
3. Detall de la factura.

Les dades de l’emissor i del client hauran d’incloure la informació necessària per identificar-los, com ara:

- Nom o raó social.
- NIF o CIF.
- Adreça.
- Població.
- Codi postal.
- Telèfon o correu electrònic, si correspon.

El detall de la factura contindrà un o més articles. Cada article haurà d’incloure:

- Descripció.
- Preu unitari.
- Quantitat.
- Import total.

Cada article tindrà els atributs següents:

- `codi`: identificador únic i obligatori de tipus `ID`.
- `tipus`: atribut opcional amb un dels valors següents:
  - `llibre`
  - `dvd`
  - `altres`

Els articles que tinguen una oferta podran incloure un element buit anomenat `oferta`. Aquest element serà opcional.

L’import total de cada article s’indicarà mitjançant un atribut obligatori.

- **Lliurament**

S’haurà de lliurar un únic fitxer XML que continga:

- La declaració XML.
- La DTD interna.
- Les dades completes d’una factura.

La factura haurà de tindre almenys tres articles i haurà d’incloure:

- Un article amb l’element `oferta`.
- Un article sense l’atribut opcional `tipus`.
- Un article amb una quantitat superior a una unitat.

El document haurà d’estar ben format i validar correctament respecte de la DTD.

### Pràctica 3 — Catàleg de videojocs

Crea un document XML que represente un catàleg de videojocs i defineix la seua estructura mitjançant una DTD externa.

- **Estructura general**

El catàleg estarà dividit en dos blocs:

1. Una llista de plataformes.
2. Una llista de videojocs.

El document haurà de contindre almenys una plataforma i un videojoc.

- **Plataformes**

De cada plataforma s’haurà d’indicar:

- Nom.
- Fabricant.

Cada plataforma tindrà un atribut `id`:

- Serà obligatori.
- Serà de tipus `ID`.
- Identificarà la plataforma de manera única.

- **Videojocs**

De cada videojoc s’haurà d’indicar:

- Títol.
- Estudi o empresa desenvolupadora.
- Any de publicació.
- Descripció opcional.
- Un element buit i opcional anomenat `disponible`.

Cada videojoc tindrà els atributs següents:

- `codi`: identificador únic i obligatori de tipus `ID`.
- `plataforma`: referència obligatòria de tipus `IDREF` a una plataforma declarada en el mateix document.
- `genere`: atribut obligatori amb un dels valors següents:
  - `accio`
  - `aventura`
  - `esports`
  - `estrategia`
- `format`: podrà tindre els valors `fisic` o `digital`. El valor predeterminat serà `digital`.
- `puntuacio`: atribut opcional amb un valor comprés entre `0` i `5`.

- **Fitxers**

S’hauran de crear els fitxers següents:

- `videojocs.dtd`: contindrà la definició de la DTD.
- `videojocs.xml`: contindrà les dades del catàleg i farà referència a la DTD externa.

- **Dades mínimes**

El document XML haurà d’incloure:

- Un mínim de dues plataformes.
- Un mínim de quatre videojocs.
- Un videojoc sense descripció.
- Un videojoc sense especificar l’atribut `format`, de manera que utilitze el valor predeterminat.
- Un videojoc sense l’element `disponible`.
- Un videojoc sense puntuació.
- Videojocs associats correctament a les plataformes mitjançant `IDREF`.

Els dos fitxers hauran d’estar ben formats i el document XML haurà de validar correctament respecte de la DTD externa.

### Pràctica 4 — Repositori de programari

Crea un document XML que represente un repositori de programari i defineix la seua estructura mitjançant una DTD externa.

- **Informació general del repositori**

El document haurà d’incloure:

- Nom del repositori.
- Categoria o temàtica principal.
- Una llista no buida de programes.

- **Programes**

De cada programa s’haurà d’indicar:

- Nom.
- Una o més etiquetes.
- Un o més desenvolupadors.
- Un o més fitxers disponibles per a descarregar.

Cada programa tindrà els atributs següents:

- `id`: identificador únic i obligatori de tipus `ID`.
- `tipus`: podrà tindre els valors `lliure` o `comercial`. El valor predeterminat serà `lliure`.
- `puntuacio`: valor opcional comprés entre `0` i `5`.

- **Desenvolupadors**

De cada desenvolupador s’haurà d’indicar:

- Nom.
- Cognoms.
- Correu electrònic.
- Tipus de desenvolupador.
- Empresa, si correspon.
- Imatge o fotografia opcional.

El tipus de desenvolupador s’haurà de representar mitjançant un atribut amb un conjunt tancat de valors definits en la DTD.

L’empresa serà opcional, ja que no tots els desenvolupadors han de pertànyer a una empresa.

La imatge serà un element buit i tindrà:

- Un atribut obligatori amb la ruta del fitxer.
- Un atribut que indique el format de la imatge.
- Els formats permesos seran `png`, `jpg` i `gif`.

- **Fitxers de programari**

De cada fitxer s’haurà d’indicar, en aquest ordre:

1. Nom del fitxer.
2. Mida.
3. URL de descàrrega.
4. Suma de verificació o `checksum`.
5. Data i hora de pujada.

La URL es representarà mitjançant un element buit amb un atribut obligatori que continga l’adreça.

La data de pujada haurà de permetre identificar separadament:

- Dia.
- Mes.
- Any.
- Hora.
- Minuts.

Aquesta estructura haurà de permetre buscar o classificar els fitxers segons qualsevol dels components de la data.

- **Entitats**

La DTD haurà d’utilitzar almenys una entitat de paràmetre per reutilitzar una definició comuna, com ara:

- Els possibles valors de les puntuacions.
- Els formats d’imatge.
- Una estructura que aparega més d’una vegada.

- **Fitxers**

S’hauran de crear els fitxers següents:

- `repositori.dtd`: contindrà la definició completa de la DTD.
- `repositori.xml`: contindrà les dades del repositori i farà referència a la DTD externa.

- **Dades mínimes**

El document XML haurà d’incloure:

- Un mínim de tres programes.
- Almenys un programa comercial.
- Almenys un programa que utilitze el valor predeterminat `lliure`.
- Un programa sense puntuació.
- Un programa amb més d’una etiqueta.
- Un programa amb més d’un desenvolupador.
- Un desenvolupador sense empresa.
- Un desenvolupador amb imatge.
- Un programa amb més d’un fitxer disponible.

Els dos fitxers hauran d’estar ben formats i el document XML haurà de validar correctament respecte de la DTD externa.
